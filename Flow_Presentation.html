1. Seeker Experience Frontend Intake
  • Initiation Intake: Seeker completes registration form with credentials, phone, address, and practice tier.
  • Mandatory Purpose Essay: Submits personal resolve (20-1000 characters) detailing reason for embarking on Bhairava Sādhana.
  • Queue Confirmation: Redirected to login with confirmation: "Application queued for Guruji / Admin verification".
  • Pending Advisory: Login attempts while unapproved show review status without exposing internal paths.
  • Post-Approval Session: Once verified, login succeeds immediately, beginning the 48-day Mandala 1 timer.
2. Security & DB Gateway Middleware
  • Validation Engine: WTForms validates email structure, password complexity, and username uniqueness.
  • Cryptographic Salting: Password hashed via Werkzeug PBKDF2:SHA256 with secure unique salt.
  • Gated Record Creation: User committed to DB with is_approved = False, is_active = True.
  • Access Gatekeeper: can_login() returns False for unapproved accounts.
  • Admin Notification Hook: inject_admin_notifications increments pending count badge on admin console.
  • Approval Event Trigger: Stamps approved_at, records approved_by, and initializes mandala_1_started_at.
3. Admin Governance Mentorship Desk
  • Header Pending Alert: Gold badge in top bar notifies admin of waiting applications.
  • Seeker Management Desk: Admin accesses /auth/admin/users with status filters.
  • Sincerity Audit: Admin opens modal to read applicant's purpose essay and spiritual experience level.
  • Tri-State Decision Gate:
    • Approve: Unlocks Mandala 1 & sets stage clock.
    • Reject: Sets is_active=False.
    • Suspend: Revokes session immediately.
  • Direct Guidance: Admin can dispatch welcome guidance via built-in mentorship chat.

✦ Data Architecture

Core Entities & Relational Data Model

User Model Primary Seeker
  • id (Primary Key)
  • username, email, password_hash
  • full_name, phone, address
  • role ('admin' / 'user')
  • is_approved, is_active
  • practice_level, purpose
  • Stage access flags (1-9)
  • Devi mandala access flags (1-3)
  • Start & completion timestamps
StageAccessRequest Progression Queue
  • id (Primary Key)
  • user_id (FK ➔ User)
  • stage_number (1-9 or 101-103)
  • status ('pending' / 'approved' / 'rejected')
  • requested_at (DateTime)
  • reviewed_at (DateTime)
  • reviewed_by (FK ➔ User)
  • notes (Admin remarks)
ChatMessage Guidance Stream
  • id (Primary Key)
  • sender_id (FK ➔ User)
  • recipient_id (FK ➔ User, optional)
  • message (Text body)
  • timestamp (DateTime)
  • is_read (Boolean flag)
  • is_from_admin (Boolean flag)
  • to_dict() JSON serializer
Donation & Mandala Offerings & Pledges
  • DonationPurpose: name, desc, is_active
  • OfflineDonation: donor_name, amount, currency, purpose_id, payment_method, is_verified, donor_id, worksheet
